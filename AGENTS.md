# AGENTS.md

## Commands

### Install dependencies
```bash
npm run install:all
```

### Run frontend (dev server, http://localhost:5173)
```bash
npm run dev:frontend
```

### Run backend (Hono API server, http://localhost:3001)
```bash
npm run dev:backend
```

### Run all checks (lint + types + unit tests + e2e)
```bash
npm run check
```

This is the single command CI runs. Use it before pushing.

### Individual check commands
```bash
npm run lint        # oxlint — frontend and backend
npm run typecheck   # tsc --noEmit — frontend and backend
npm run test:unit   # vitest — frontend and backend
npm run test:e2e    # Playwright e2e (starts servers automatically)
npm test            # alias for test:unit (no e2e)
```

## Generated files — do not edit by hand

The following files are produced by `npm run generate` from `contract/src/main.tsp` (TypeSpec source of truth). **Never edit them manually.**

| File / directory | Source | Regenerated by |
|---|---|---|
| `openapi.yaml` | `contract/src/main.tsp` | `npm run generate:openapi` |
| `frontend/src/generated/` | `openapi.yaml` | `npm run generate:client` |

If you change the TypeSpec contract, run `npm run generate` and commit both the `.tsp` change and the regenerated files in the same commit. CI (`generate-check` job) verifies this by re-running `npm run generate` and asserting `git diff --exit-code` on those paths — any drift fails the build.

## Commit format

All commits **must** follow [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <description>

Closes #<issue-number>
```

**Types:** `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

Every commit that implements or closes a GitHub issue **must** include a footer referencing the issue number. Use `Closes #N` to auto-close on merge, or `Refs #N` when the commit is partial work.

**Examples:**
```
feat(backend): replace static slots with rolling generation

Closes #12
```
```
fix(api): handle empty bookings list

Refs #15
```
```
docs: update installation instructions

Closes #10
```

This convention is required — release-please reads commit messages to auto-generate changelogs and bump versions when PRs are merged into `main`. Issue references create traceability between tickets and commits, enabling partial rollbacks.
